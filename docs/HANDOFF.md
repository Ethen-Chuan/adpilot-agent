# AdPilot Agent 项目交接文档

## 1. 项目当前状态概述

AdPilot Agent 目前是一个功能完善的 Web Demo，实现了基于真实 LLM 的广告投放分析 Agent 核心功能，并具备良好的用户体验（输入校验、历史记录、反馈闭环、UI 打磨）。在无 API Key 的情况下，可自动降级为 Fallback 模式，保证核心流程可用。

## 2. 当前可演示功能

- **广告投放信息输入**：用户可填写商品名称、卖点、目标市场、投放平台、日预算和核心目标。
- **前端输入校验**：确保用户输入数据的有效性。
- **示例数据填充**：一键填充示例数据，方便快速演示。
- **智能分析**：
  - **Live 模式**：通过配置 `OPENAI_API_KEY`，可调用真实 LLM 生成人群洞察、素材方向、投放计划和优化建议。
  - **Fallback 模式**：在无 API Key 时，自动使用 mock 数据进行演示。
- **Agent 执行步骤**：实时展示 Agent 的分析流程。
- **分析结果展示**：以卡片形式清晰展示四项分析结果，并支持内容复制。
- **历史记录**：保存最近 5 次分析记录，可点击回填表单并查看结果。
- **用户反馈**：对分析结果进行“有帮助”或“需要优化”的反馈，并持久化。
- **UI/UX**：界面美观，交互流畅，包含 Loading、空状态、错误状态等。

## 3. 下一位接手者第一步该做什么

1.  **克隆仓库**：`git clone <repo-url>` (如果已在 Manus 环境中，则无需此步)。
2.  **进入项目目录**：`cd adpilot-agent`。
3.  **安装依赖**：`pnpm install`。
4.  **配置环境变量**：将 `.env.example` 复制为 `.env.local`，并填入 `OPENAI_API_KEY`。如果仅需演示 Fallback 模式，可留空。
5.  **启动开发服务器**：`pnpm run dev`。
6.  **访问应用**：在浏览器中打开 `http://localhost:3000`。
7.  **阅读文档**：按照“优先阅读顺序”阅读相关文档，全面了解项目。

## 4. 优先阅读顺序

1.  `README.md`：项目概览、运行方式、技术栈。
2.  `docs/PROJECT_STATE.md`：项目当前状态、已完成/未完成功能、API 结构、本地存储等详细信息。
3.  `docs/HANDOFF.md` (本文件)：快速上手指南、低积分保护策略。
4.  `docs/NEXT_STEPS.md`：后续开发计划和任务。
5.  `docs/CHANGELOG.md`：项目版本变更历史。
6.  `docs/FILE_MAP.md`：核心文件功能速查。

## 5. 哪些文件最核心

- `app/page.tsx`: 前端主页面，整合所有 UI 和交互逻辑。
- `app/api/analyze/route.ts`: 后端 API 路由，Agent 的入口。
- `lib/agent/orchestrator.ts`: Agent 核心编排逻辑。
- `lib/agent/toolRouter.ts`: 工具调度逻辑。
- `lib/services/llm.ts`: LLM API 调用封装。
- `lib/tools/*.ts`: 各个具体工具的实现。
- `lib/history.ts`: 历史记录和反馈的本地存储逻辑。
- `lib/types.ts`: 全局类型定义。

## 6. 低积分保护策略

在资源（如积分）有限的情况下，请遵循以下策略以最大化开发效率和项目可用性：

- **不要重构目录结构**：保持现有文件和目录结构，避免不必要的迁移成本。
- **不要大面积更换技术栈**：继续使用 Next.js, React, Tailwind CSS, TypeScript。
- **优先增量修改**：在现有代码基础上进行功能添加和优化，而非推倒重来。
- **优先保住核心功能**：如果积分紧张，优先确保以下功能正常运行：
  - 项目可正常启动和运行 (`pnpm run dev`)
  - 表单可提交，并能返回分析结果（Live 或 Fallback 模式）
  - 历史记录功能可用，可回填和查看结果
- **积分紧张时优先修文档**：若只剩少量积分，优先确保 `README.md` 和 `docs/` 目录下的所有文档是最新的、最清晰的，而不是投入到花哨的 UI 优化或非核心功能开发中。清晰的文档是跨账号续作和低成本继续开发的关键。
